# Contragenti — руководство пользователя

Утилита для поиска юридических лиц Молдовы на портале **date.gov.md** и ведения
локальной базы контрагентов. Есть графический интерфейс, локальная база SQLite,
экспорт (CSV / Excel / Markdown) и **локальный HTTP-API** для интеграции с 1С,
браузером и другими программами.

Версия: **1.0**

---

## 1. Назначение

- Поиск компаний по названию / имени руководителя / IDNO
  (страница `open/company-search`).
- Получение полной карточки компании по IDNO
  (страница `open/company-details`): базовые данные, учредители, задолженность
  перед бюджетом.
- Накопление всех найденных данных в локальной базе `companies.db` (SQLite).
- Экспорт данных для дальнейшей обработки, в т.ч. **Markdown для ИИ**.
- Возврат карточки контрагента во внешние системы в формате **XML**.

> **Важно.** Страницы портала защищены невидимой reCAPTCHA, поэтому запросы к
> сайту выполняются через **реальный браузер Chrome** (Selenium). Обычно капча
> проходит автоматически; если Google покажет проверку — решите её в открывшемся
> окне браузера.

## 2. Установка и запуск

Требуется **Python 3.12+** с поддержкой Tkinter и установленный **Google Chrome**.

Установка с нуля (после клонирования репозитория):

```bash
python3.12 -m venv .venv
./.venv/bin/python -m pip install -r requirements.txt
```

> **macOS (Homebrew):** если появляется `ModuleNotFoundError: No module named
> '_tkinter'`, установите Tk: `brew install python-tk@3.12`.

Запуск:

```bash
cd "/Users/pt/Projects.AI/DATE.gov/Contragenti" && ./run.sh
```

или напрямую:

```bash
./.venv/bin/python company_search.py
```

### Аргументы командной строки

| Аргумент | По умолчанию | Назначение |
|---|---|---|
| `--port N` | `9393` | Порт локального HTTP-API |
| `--host H` | `127.0.0.1` | Адрес прослушивания API |
| `--lang ru\|ro\|en` | `ru` | Язык интерфейса при старте |
| `--q "ТЕКСТ"` | — | Стартовать сразу с этим поиском |
| `--pick` | выкл. | Одноразовый режим: дождаться выбора, вывести XML и выйти |
| `--out FILE` | — | Файл для записи XML (вместе с `--pick`) |
| `--no-server` | выкл. | Не запускать HTTP-API |
| `--no-tray` | выкл. | Не создавать иконку в трее |

Пример одноразового вызова из внешней программы (получить карточку и выйти):

```bash
./.venv/bin/python company_search.py --q "UNISIM" --lang ru --pick --out card.xml --no-server
```

## 3. Интерфейс

Окно состоит из трёх зон: **вкладки-мастер** (сверху), **карточка компании**
(снизу) и **строка состояния**.

### 3.1. Вкладка «Онлайн-поиск»

- Поле ввода критерия, кнопка **«×»** (очистка) и **«Поиск»**.
- **«Показывать из БД»** — после онлайн-поиска и сохранения показывать
  накопленную выборку из SQLite (по умолчанию включено).
- **«Скрытый браузер»** — headless-режим. **Не рекомендуется**: в нём Google
  почти всегда требует ручную капчу, и запрос завершается по таймауту.
- Кнопка **«×»** очищает поле и показывает **все** сохранённые записи из БД.
  Пустой поиск также показывает всю базу.

### 3.2. Вкладка «Только БД (офлайн)»

Поиск исключительно по локальной базе (`LIKE` по IDNO, названию, руководителям).
К сайту не обращается. Пустой запрос — вся база.

### 3.3. Карточка компании (master-detail)

При выборе строки в любой таблице снизу открывается карточка:

- Название (крупно) и компактная сетка полей: IDNO, дата регистрации, форма,
  ликвидирована, юр. адрес, руководители.
- Поле IDNO и кнопки:
  - **«Данные по IDNO»** — запрос детальной карточки с сайта (капча), с
    сохранением в БД. Если детали уже есть в БД — они и показываются.
  - **«Экспорт MD»** — сохранить карточку в Markdown.
  - **«XML карточки»** — скопировать XML текущей карточки в буфер обмена.
  - **«↩ Вернуть контрагента»** — появляется **только** при внешнем вызове
    (`/pick`). Возвращает выбранную карточку вызвавшей программе; браузеру
    показывается страница с основными полями и полным XML.
- Текстовая область — фрагменты ответа (базовые данные, учредители, долги).

### 3.4. Языки интерфейса

Меню **«Язык»**: English / Русский / Română — переключается на лету
(меню, вкладки, кнопки, заголовки колонок, подписи карточки, статусы, экспорт MD).

## 4. База данных SQLite

Файл `companies.db` рядом со скриптом. Таблица `companies`:

| Колонка | Описание |
|---|---|
| `key` | Первичный ключ: IDNO, либо `name:<Название>` если IDNO пуст |
| `idno`, `denumire`, `administratori`, `inregistrare` | Базовые поля из поиска |
| `forma_juridica`, `lichidata`, `adresa` | Из детальной карточки |
| `details_text` | Полный текст фрагментов карточки |
| `founders_json` | Учредители: `[{"name","share"}]` |
| `debts_json` | Долги: `[{"nr","type","sum"}]` |
| `updated_at` | Дата/время последнего обновления записи |

**Правило сохранения (upsert по IDNO):** если IDNO уже есть — обновляются только
непустые поля (детали не затираются частичными данными поиска); иначе —
вставляется новая запись. Схема старой БД **мигрируется** автоматически
(добавляются недостающие колонки).

## 5. Экспорт

Меню **«Экспорт»**:

- **Вся БД → CSV** — разделитель `;`, кодировка UTF-8 с BOM (открывается в Excel).
- **Вся БД → Excel** — файл `.xlsx`.
- **Выбранные → MD (папка)** — по одному `.md`-файлу на каждую выделенную строку
  активной вкладки (множественный выбор — Ctrl/Shift+клик). Имя файла — IDNO.
- **Текущую → MD** — карточка текущей компании в Markdown.

### Структура Markdown

Markdown содержит базовые поля списком, **учредителей** и **задолженность**
отдельными таблицами, а также блок с полным текстом карточки. Такой формат удобно
передавать ИИ-системам для дальнейшего анализа. Пример:

```markdown
# CENTRUL … UNISIM-SOFT S.R.L.

- **IDNO:** 1003600116460
- **Дата регистрации:** 30.03.2001
- **Форма:** Societate cu răspundere limitată
- **Юр. адрес:** mun. Chişinău, …

## Учредители
| Имя | Доля (%) |
| --- | ---: |
| TUHARI PAVEL | 100,00 |

## Задолженность перед бюджетом
| № | Тип бюджета | Сумма (MDL) |
| ---: | --- | ---: |
| 1 | Bugetul de stat și local | 0,00 |
| 2 | Bugetul de stat | 180,78 |
```

## 6. Локальный сервер и трей

При запуске (если не указан `--no-server`) поднимается локальный HTTP-API
(по умолчанию `http://127.0.0.1:9393`). При закрытии окна крестиком программа
**не завершается**, а сворачивается в фон — сервер продолжает отвечать на
запросы. Полный выход — меню **«Файл → Выход»** или пункт трея **Quit**.

Иконка в трее создаётся, если доступна библиотека `pystray` и это позволяет
платформа. На части систем (например, macOS без запуска в главном потоке) трей
может быть недоступен — тогда программа просто продолжает работать в фоне, а
повторный вызов `GET /open` снова показывает окно.

При вызове из веб-системы можно передать адрес возврата
(`/pick?...&return_to=<URL>&state=<ид>`) — тогда после выбора браузер
**вернётся в вызывающую систему** с данными компании в query-строке.

Полное описание API и сценарии интеграции — в **[API_ru.md](API_ru.md)**;
устройство программы — в **[TECHNICAL_ru.md](TECHNICAL_ru.md)**; почему это
нативное приложение — в **[NATIVE_ru.md](NATIVE_ru.md)**.

## 7. Типичные сценарии

1. **Ручной поиск и накопление базы.** Онлайн-поиск → результаты сохраняются →
   переключаетесь на «Только БД» для быстрого офлайн-поиска.
2. **Досье на компанию.** Выбрать строку → «Данные по IDNO» → «Экспорт MD» —
   получить структурированный файл для ИИ.
3. **Интеграция с 1С.** 1С не нашла контрагента в своей базе → вызывает
   `GET /pick?q=<фильтр>&lang=ru` → у пользователя открывается окно с готовым
   поиском → он выбирает компанию и жмёт «XML карточки» → 1С получает XML.

---

## 8. Ограничения

- Нужен установленный **Google Chrome**; Selenium сам загружает драйвер.
- Онлайн-запросы зависят от reCAPTCHA — **не** используйте «Скрытый браузер».
- Для строк без IDNO детальная карточка недоступна (нет ключа для запроса).
