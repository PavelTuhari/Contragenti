# Почему Contragenti — нативное приложение

Документ отвечает на вопрос «в каком смысле это нативное (native) приложение,
если внутри есть HTTP-сервер и используется браузер?».

**Короткий ответ.** Нативность определяется **моделью исполнения и доступом к
операционной системе**, а не тем, какие протоколы приложение использует внутри.
Contragenti — обычный процесс ОС с собственным окном, прямым доступом к диску,
буферу обмена, системному трею и правом запускать другие процессы. Ничего из
этого недоступно веб-странице.

**Практическая причина, почему приложение именно нативное.** Форма портала
защищена невидимой reCAPTCHA — серверный скрапер и `curl` получают `HTTP 400`.
Валидный токен выдаётся только реальному браузеру, поэтому приложение **управляет
настоящим Google Chrome** и проходит форму, как живой пользователь (это работа с
публичной формой штатным способом, а не обход защиты). Полученные данные при этом
**пишутся напрямую в локальную SQLite**. Оба требования — управление другим
процессом и прямая запись в локальный файл — веб-странице недоступны в принципе;
именно они и делают утилиту настольной программой.

---

## 1. Шесть признаков нативности

### 1.1. Модель исполнения — процесс ОС, а не песочница браузера

Приложение запускается как самостоятельный процесс с собственным PID, работает
с правами пользователя и напрямую использует системные вызовы. Веб-приложение
исполняется внутри браузерной песочницы, где доступ к системе намеренно
ограничен (нет произвольного чтения диска, нет запуска процессов, нет
прослушивания портов).

### 1.2. Окно рисует оконная система, а не движок вёрстки

Интерфейс построен на **Tk/ttk**, который создаёт настоящее окно оконной
системы:

| Платформа | Что используется |
|---|---|
| macOS | Cocoa/Aqua: окно `NSWindow`, системная строка меню, нативные диалоги файлов |
| Windows | Win32: окно и меню, диалоги `GetOpenFileName` |
| Linux | X11 / Wayland через Tk |

Виджеты `ttk` берут **тему оформления платформы**, поэтому приложение выглядит
как программа этой ОС, а не как веб-страница. Меню «Файл / Экспорт / Язык» —
системное меню приложения. Диалоги сохранения файлов — системные диалоги.

### 1.3. Прямой доступ к файловой системе

- База данных — локальный файл `companies.db` (**SQLite**), лежит рядом с
  программой и принадлежит пользователю.
- Экспорт CSV / Excel / Markdown пишется **в любую выбранную папку**, включая
  массовую выгрузку десятков `.md`-файлов за одну операцию.

Браузерная страница так не может: она работает с виртуальным хранилищем
(IndexedDB / localStorage), а каждый файл отдаёт только через диалог загрузки.

### 1.4. Фоновый резидент и системный трей

Программа продолжает работать после закрытия окна: живёт в **системном трее**,
откуда её можно развернуть или завершить. Это классический жизненный цикл
десктопной утилиты (как менеджер облачного диска или мессенджер).

### 1.5. Интеграция с ОС

- **Буфер обмена** — кнопка «XML карточки» кладёт XML в системный буфер.
- **Управление другим приложением** — утилита запускает и автоматизирует
  **Google Chrome** (через WebDriver), то есть выступает управляющим процессом
  по отношению к другой нативной программе.
- **Прослушивание TCP-порта** — приложение поднимает собственный сервер на
  `127.0.0.1`. Веб-страница в принципе не может открыть слушающий сокет.

### 1.6. Автономность

Нет backend-сервера, нет аккаунтов, нет деплоя и нет обязательного интернета:
вкладка **«Только БД»** полностью работает офлайн по локальной базе.
Приложение распространяется как программа (репозиторий / архив / при желании
`.app` или `.exe` через PyInstaller), а не как ссылка на сайт.

## 2. Разбор частых возражений

### «Но внутри есть HTTP-сервер — значит это веб-приложение»

**Нет.** HTTP здесь — это **транспорт межпроцессного взаимодействия (IPC)**,
а не способ доставки приложения пользователю. Сервер:

- слушает только `127.0.0.1` — извне машины он недоступен;
- никуда не публикуется и не имеет домена;
- существует ровно для того, чтобы **1С** (и любая другая программа) могла
  вызвать утилиту и получить XML.

Так устроены многие бесспорно нативные программы: Docker Desktop, локальные
серверы IDE, клиенты синхронизации. HTTP выбран потому, что это **единственный
транспорт, одинаково доступный из 1С, из браузера, из PowerShell и из bash**, —
в отличие от COM (только Windows) или Unix-сокетов (не Windows).

> Аналогия: наличие розетки Ethernet в холодильнике не превращает холодильник в
> сетевое оборудование.

### «Но используется браузер Chrome — значит это веб-приложение»

**Нет.** Chrome здесь — **внешний инструмент**, а не среда исполнения программы.
Портал `date.gov.md` защищён невидимой reCAPTCHA, и единственный корректный
способ получить данные — пройти форму так же, как это делает человек. Утилита
управляет Chrome как отдельным нативным процессом, а весь свой интерфейс,
логику и хранилище держит у себя.

Это ровно та же модель, что и у нативного приложения, которое вызывает Word для
печати документа или ffmpeg для конвертации видео: **автоматизация другой
программы — признак нативности, а не веба** (веб-страница чужой программой
управлять не может).

### «Но это Python, а не C++ — значит не нативное»

Нативность — про **модель исполнения и доступ к ОС**, а не про способ
компиляции. По этой логике «ненативными» пришлось бы объявить приложения на
C#/WPF (исполняются в CLR), Java/Swing (JVM) и большинство корпоративного
десктопа. Contragenti имеет тот же уровень доступа к системе, что и программа
на C++: файлы, процессы, сокеты, трей, буфер обмена.

Для сравнения — **Electron-приложения** (VS Code, Slack) считаются нативными
desktop-программами, хотя их интерфейс буквально отрисовывает встроенный
Chromium. Contragenti использует для интерфейса Tk, что **ближе к системе**, чем
Electron.

## 3. Итоговая таблица

| Критерий | Веб-приложение | **Contragenti** | Классический desktop (C++/Qt) |
|---|---|---|---|
| Где исполняется код | Песочница браузера | **Процесс ОС** | Процесс ОС |
| Окно | Вкладка браузера | **Окно ОС (Tk/Cocoa/Win32)** | Окно ОС |
| Доступ к диску | Ограничен | **Полный** | Полный |
| Запуск других процессов | Нет | **Да (Chrome)** | Да |
| Слушать TCP-порт | Нет | **Да (9393)** | Да |
| Системный трей | Нет | **Да** | Да |
| Работа офлайн | Обычно нет | **Да** | Да |
| Нужен сервер/деплой | Да | **Нет** | Нет |

**Вывод.** По каждому практическому критерию Contragenti ведёт себя как
desktop-программа. Внутренний HTTP-сервер и управляемый браузер — это
инструменты интеграции и получения данных, а не признаки веб-приложения.
