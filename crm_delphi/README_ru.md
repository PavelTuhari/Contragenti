# Demo CRM — SDK-интеграция с Contragenti

Демонстрационное CRM-приложение на **Delphi 10.2 Tokyo** (VCL + FireDAC/SQLite),
которое ведёт свою личную базу клиентов и заводит новых контрагентов, вызывая
приложение **Contragenti**: то открывается на поиске по государственному
реестру date.gov.md, а после выбора возвращает XML полной карточки.

```
CRM  ──запуск с фильтром──►  Contragenti (поиск в date.gov.md)
                                     │ пользователь выбирает контрагента
CRM  ◄──── XML карточки ──────────────┘
  └─ разбор XML → запись в личную SQLite (дедупликация по IDNO)
```

Так CRM не знает ничего о reCAPTCHA, Selenium и структуре портала — вся эта
работа остаётся внутри Contragenti, а наружу отдаётся простой XML-контракт.

Пошаговая установка Demo CRM и Contragenti на Windows:
**[INSTALL_WINDOWS_ru.md](../INSTALL_WINDOWS_ru.md)**
([открыть HTML как страницу](https://cdn.jsdelivr.net/gh/PavelTuhari/Contragenti@main/docs/ustanovka-demo-crm-windows.html)).

## Интерфейс — как у бесплатной EspoCRM

Окно повторяет тему «Espo» (палитра и размеры взяты из исходников
EspoCRM, `frontend/less/espo`): левая навигация 232 px с пунктами
Главная / Клиенты / Контакты / Лиды / Сделки / Календарь / Настройки
(активный пункт `#dee1e7`), верхняя полоса с глобальным поиском, «+»
(быстрое создание), уведомлениями и пользователем; заголовок раздела
с синей кнопкой `btn-primary` (`#5589ca`) «Создать клиента», строка
фильтров (пресет «Все / Добавлены сегодня / С юридическим адресом» +
поиск), белая таблица с чекбоксами и приглушёнными заголовками
колонок, панель карточки выбранной записи в две колонки label/value,
дашлеты на «Главной». Строка сообщений внизу использует цвета
`label-state` EspoCRM (primary / success / warning / danger).

## Функционал для небольшой фирмы (торговля, услуги, производство)

| Раздел | Что умеет |
|---|---|
| **Рабочий стол** | главный экран: большие плитки этапов «от контракта до денег» — Предложение / Переговоры / Готово к заказу, затем Ожидает аванс / В работе / Готово к отгрузке / Отгружено — ждём оплату / Закрыто. На каждой плитке количество, сумма и маркер: «всё в срок» зелёным или «запаздывает N · сумма» красным. Нажатие открывает раздел с уже выставленным фильтром. Здесь же полоса связи с ERP и сводки последних заказов и ближайших задач |
| **Канбан** | доска работ с колонками-этапами. Карточку **тянут мышью** между колонками (во время переноса за курсором идёт подсказка, целевая колонка подсвечивается) либо переводят кнопками «← Назад» / «Вперёд →». Двойной клик открывает запись в её разделе. Три доски: заказы (аванс → работа → отгрузка → оплата → закрыто), сделки по воронке, задачи по срокам. Перенос выставляет те же поля, по которым считаются этапы, поэтому доска и плитки рабочего стола всегда согласованы |
| **План работ (Гант)** | последовательность работ во времени: строка — заказ, под ним отступом его операции (строки заказа) в порядке исполнения. Полосу **тянут мышью**: за середину — сдвиг всего заказа, за края — изменение даты начала или срока (курсор подсказывает, что будет); пока тянешь, видно предпросмотр, в базу дата уходит только при отпускании. Двойной клик открывает заказ. Светлая полоса — план, синяя — идёт, красная — выход за срок, зелёная — закрыт; вертикальная линия — сегодня. Фильтры: производство / все заказы / только незакрытые |
| **Клиенты** | заведение из реестра date.gov.md через SDK Contragenti (IDNO, форма, адрес, руководитель), дедупликация по IDNO; в карточке — тип (клиент/поставщик/партнёр), телефон, e-mail, контактное лицо |
| **Контакты** | люди у клиента: должность, телефон, e-mail, заметки |
| **Лиды** | источник (сайт/звонок/рекомендация/выставка/реклама), статус (новый → в работе → конвертирован/отказ), кнопка **«В клиенты»** создаёт клиента и закрывает лид |
| **Сделки** | воронка: Новая → Предложение → Переговоры → Выиграна/Проиграна, сумма, дата закрытия, привязка к клиенту; пресеты «Открытые / Выигранные / Проигранные» |
| **Номенклатура** | единый справочник: **товар**, **услуга**, **изделие** собственного производства; ед. изм., цена, НДС, остаток; пресет «Нет на складе» |
| **Заказы** | вид **продажа / услуга / производство**, статусы (черновик → подтверждён → в работе → выполнен → оплачен / отменён), **аванс, оплачено, срок, дата отгрузки**, строки заказа с ценой из номенклатуры и итогом; кнопка **«Провести»**: продажа списывает остаток, производство приходует изделия, услуги остатки не трогают. Пресеты повторяют плитки рабочего стола, включая «Запаздывает» |
| **Календарь** | задачи / звонки / встречи со сроком, привязкой к клиенту и сделке; пресеты «Открытые / Сегодня / Просроченные»; кнопка «Выполнено» |
| **Отчёты** | пять ключевых отчётов с предпросмотром и выгрузкой в **Excel (.xlsx)** и **PDF**: процесс исполнения заказов, дебиторская задолженность, продажи по клиентам, воронка продаж, остатки номенклатуры |

## Связь с ERP una.md

Рабочий стол показывает состояние связи и умеет отправлять данные в ERP
через HTTP-API хаба (`hub/app.py`): `GET /api/v1/health` — проверка,
`POST /api/v1/batches` — приём gzip-копии базы (заголовки `X-API-Key`,
`X-Client-Id`), `GET /api/v1/batches/<id>` — статус импорта. Хаб переносит
записи в схемы Oracle una.md. Адрес и ключ задаются в «Настройках» и
хранятся в `crm.ini` (секция `[erp]`), в репозиторий не попадают.

## Выгрузка в Excel и PDF — без внешних библиотек

- **XLSX** (`uXlsx.pas`) — настоящий Open XML: zip собирается через
  `System.Zip`, строки пишутся как `inlineStr`, числа остаются числами
  (проверено чтением через openpyxl), деньги с форматом `#,##0.00`.
- **PDF** (`uPdf.pas`) — свой генератор со **встроенным системным
  TrueType** (Arial/Tahoma) как CIDFontType2 + Identity-H: стандартные
  шрифты PDF не содержат кириллицы. Разбираются таблицы `head`, `hhea`,
  `maxp`, `hmtx` и `cmap` (формат 4) — из них берутся глифы и их ширины,
  иначе просмотрщик расставит символы неверно. Альбомная A4 с разбивкой
  на страницы.

Все разделы, кроме «Клиентов», построены одной универсальной страницей
`uEntityPage.pas` по описаниям полей из `uCrmData.pas` — новая сущность
добавляется записью в `EntityDefs`, а не новой формой. Редактор записи —
панель внутри страницы (без модальных окон), удаление — по второму
нажатию, ошибки валидации — в строке сообщений.

## Сборка

Нужна установленная RAD Studio 10.2 Tokyo (переменная `BDS` или путь по
умолчанию в `build.bat`).

```bat
build.bat
```

Получится `ContragentiCRM.exe`. В IDE проект тоже открывается — файлы `.pas`
самодостаточны, форма создаётся кодом, `.dfm` не нужен.

> Исходники сохранены в UTF-8 **с BOM** — иначе `dcc32` читает их как ANSI и
> портит кириллические строки в интерфейсе.

## Запуск

```bat
ContragentiCRM.exe                     графический интерфейс
ContragentiCRM.exe --import card.xml   импорт карточки из XML (без окна)
ContragentiCRM.exe --selftest          проверка базы и разбора XML
ContragentiCRM.exe --gui-test [dir]    GUI-самотест со снимками и report.html
ContragentiCRM.exe --seed-demo [база]  полный набор тестовых данных (идемпотентно)
ContragentiCRM.exe --dml-test          DML-тест всех сущностей во временной базе
```

Правило проекта ([AGENTS.md](../AGENTS.md)): при любой доработке генератор
(`uTestData.pas`) обновляется вместе с сущностью, затем обязательно
прогоняются `--seed-demo`, `--dml-test` (0 FAIL) и `--gui-test`.

Интерфейс без модальных окон: все сообщения выводятся в строку внизу окна
и различаются цветом (серый — информация, зелёный — успех, янтарный —
предупреждение/запрос подтверждения, красный — ошибка). Настройки
раскрываются панелью внутри окна, удаление подтверждается повторным
нажатием «Удалить». Необработанные исключения тоже попадают в строку
сообщений (`Application.OnException`), а не в MessageBox.

`--gui-test` работает в отдельной базе `dir\test_clients.db`, рабочая
`clients.db` не затрагивается. Дисплей не нужен: форма рисуется в память.

**Кнопка «Создать из реестра»** запускает Contragenti с введённым фильтром,
ждёт выбора и заводит выбранного контрагента. Пока чужое окно открыто, CRM
каждые 200 мс прокачивает очередь сообщений и показывает в строке снизу,
сколько уже ждёт, — иначе Windows пометила бы окно «не отвечает». Повторное
нажатие в это время отклоняется. Путь к Contragenti задаётся в «Настройках»;
если сохранённого пути нет, CRM сама ищет его рядом с программой, в
`build\exe.win-amd64-3.12`, в исходниках репозитория и в
`%LOCALAPPDATA%\Contragenti`.

Личная база — `clients.db` рядом с программой, настройки — `crm.ini`.

## SDK: как встроить в своё приложение

```pascal
uses uContragenti;

var
  Cli: TContragentiClient;
  Card: TCounterpartyCard;
begin
  Cli := TContragentiClient.Create;
  try
    Cli.LauncherExe := 'C:\...\Contragenti.exe';
    Cli.Lang := 'ru';
    if Cli.Pick('UNISIM', Card) then
      // Card.Idno, Card.Denumire, Card.Adresa, Card.Administratori,
      // Card.Founders[], Card.Debts[] ...
    else
      ShowMessage('Отменено: ' + Cli.LastError);
  finally
    Cli.Free;
  end;
end;
```

`ParseCardXml` / `ParseCardFile` доступны отдельно — если XML уже получен
другим способом (например, через локальный HTTP-API Contragenti на порту 9393).

## Проверено

- `--selftest` — разбор XML и SQLite с дедупликацией: **PASS**
- `--import sample_card.xml` — карточка заведена (клиент #1), повторный
  импорт → **DUP** (дубликат по IDNO не создаётся)
- содержимое `clients.db` сверено независимо: все поля на месте
- GUI-режим запускается, окно и список отображаются, кириллица корректна
- `--gui-test shots_gui` — **33/33**: импорт двух карточек, дубликат,
  фильтр, панель настроек, удаление без выбора, двухшаговое удаление,
  затем **реальный вызов SDK**: настоящая кнопка «Создать из реестра»
  запускает Contragenti (`python company_search.py --pick --auto-pick
  --shots-dir …`), тот возвращает XML, CRM сохраняет карточку; повторный
  вызов отсекается как дубликат. Contragenti сам снимает своё окно и
  страницы портала в каталог отчёта (`sdk_*.png`). Отчёт
  `shots_gui/report.html` со ссылками на `NN_*.png`.
- Тест выявил и помог исправить: ошибку `List(Filter)` (параметр
  задавался до SQL — исключение уходило в модальный MessageBox);
  падение Chrome 152 с опцией `excludeSwitches=enable-automation`;
  возврат карточки без деталей в auto-pick (поток поиска ещё закрывал
  Chrome, и дозагрузка деталей пропускалась).
- Портал date.gov.md после нескольких поисков подряд включает reCAPTCHA —
  auto-pick поэтому сначала берёт компанию из локальной базы-кэша
  Contragenti и идёт на портал только если её там нет. Капчу
  приложение не обходит: при таймауте Contragenti сохраняет снимок
  страницы (`sdk_0_portal_timeout.png`) и завершается без XML, CRM
  показывает янтарное «Выбор отменён».

Что **не** проверено вживую: полный цикл «кнопка → выбор в Contragenti → XML»
требует интерактивного выбора в окне Contragenti. Контракт проверен по обе
стороны — Contragenti пишет XML этого формата (`--pick --out`), CRM его
разбирает (эталон `sample_card.xml` получен из `build_card_xml`).

## Контракт XML

Contragenti в режиме `--pick --out file.xml` записывает:

```xml
<counterparty source="date.gov.md" idno="..." updated="...">
  <idno>...</idno>
  <denumire>...</denumire>
  <inregistrare>...</inregistrare>
  <forma_juridica>...</forma_juridica>
  <lichidata>...</lichidata>
  <adresa>...</adresa>
  <administratori>...</administratori>
  <founders>
    <founder name="..." share="..."/>
  </founders>
  <debts currency="MDL">
    <debt nr="..." type="..." sum="..."/>
  </debts>
  <details_text>...</details_text>
</counterparty>
```
