# Contragenti — техническая документация

Описание архитектуры, модулей и внутренних механизмов утилиты.
Пользовательское руководство — в [DOCUMENTATION_ru.md](DOCUMENTATION_ru.md),
интеграция — в [API_ru.md](API_ru.md).

- **Язык:** Python 3.12
- **Объём:** один модуль `company_search.py` (~1600 строк), без внешнего фреймворка
- **Зависимости:** `selenium`, `openpyxl`, `pillow`, `pystray`
  (см. `requirements.txt`); `tkinter`, `sqlite3`, `http.server`,
  `html.parser`, `xml.etree` — из стандартной библиотеки

```
│                                                              │
│  ┌────────────────────┐   очередь    ┌────────────────────┐  │
│  │  Главный поток     │◀─ queue.Queue ─│  BrowserWorker    │  │
│  │  Tkinter (App)     │               │  (поток на запрос) │  │
│  │  ─ окно, master-   │               │  Selenium → Chrome │  │
│  │    detail, меню    │               └────────────────────┘  │
│  └─────────┬──────────┘                          │            │
│            │                                     ▼            │
│            │                            ┌────────────────┐    │
│            │                            │ Google Chrome  │────┼──▶ date.gov.md
│            │                            │ (нативный proc)│    │
│            ▼                            └────────────────┘    │
│  ┌────────────────────┐   очередь    ┌────────────────────┐  │
│  │  SQLite            │◀─────────────▶│  ApiHandler        │  │

│                                       └────────────────────┘  │
│  ┌────────────────────┐                                       │
│  │  pystray (трей)    │─── queue ───▶ главный поток           │
│  └────────────────────┘                                       │
└──────────────────────────────────────────────────────────────┘
```

### Ключевое правило многопоточности

**Tkinter не потокобезопасен.** Все обращения к виджетам выполняются
исключительно в главном потоке. Фоновые потоки (Selenium, HTTP-сервер, трей)
**никогда** не трогают Tk напрямую — они кладут сообщения в `queue.Queue`,
которую главный поток разбирает в `App._poll_queue()` каждые 120 мс.

> Нарушение этого правила ранее приводило к падению `abort()` в Tcl/Tk на macOS
> (`PyEval_RestoreThread → fatal_error`) при клике по меню трея.

Типы сообщений очереди:

| Сообщение | Источник | Действие в главном потоке |
|---|---|---|
| `("status", текст)` | BrowserWorker | Обновить статус-бар |
| `("search_done", rows)` | BrowserWorker | Сохранить в БД, показать выборку |
| `("details_done", data)` | BrowserWorker | Сохранить детали, показать карточку |
| `("error", текст)` | BrowserWorker | Показать диалог ошибки |
| `("d2b_done", payload)` | Data2bWorker | Сохранить и показать выдачу data2b.md |
| `("d2b_error", текст)` | Data2bWorker | Сообщение в статус-бар (поиск не прерывается) |
| `("portal_no_data", текст)` | BrowserWorker | Портал ответил «Nu sunt date.» |
| `("details_none", idno)` | BrowserWorker | Карточки нет на портале: показать из БД, завершить `/pick` |
| `("open", payload)` | HTTP `/open` | Показать окно, запустить поиск |
| `("pick", payload)` | HTTP `/pick` | Режим выбора + кнопка «Вернуть контрагента» |
| `("ui", "raise"\|"quit")` | Трей | Развернуть окно / завершить программу |

## 2. Слой парсинга HTML

Портал отдаёт HTML-фрагменты, поэтому используется `html.parser` из стандартной
библиотеки (без внешних зависимостей вроде BeautifulSoup).

| Класс / функция | Назначение |
|---|---|
| `ResultTableParser` → `parse_results()` | Строки таблицы результатов поиска → список `dict` с полями `idno`, `denumire`, `administratori`, `inregistrare` |
| `DetailBasicParser` → `parse_detail_basic()` | Пары «label: value» из фрагмента «Date de bază». Отслеживает `<span class="simple-title">` и обрывает значение при входе во вложенные `<ul>`/`<table>` |
| `TablesParser` → `parse_tables()` | Все таблицы фрагмента: `{"headers": [...], "rows": [[...]]}` |
| `classify_tables()` | Классификация таблиц по заголовкам: «Cota parte» → учредители, «Suma / buget» → задолженность |

Результат классификации сохраняется в БД как JSON (`founders_json`,
`debts_json`) и далее используется в Markdown, XML и HTML-карточке.

## 3. Слой данных (SQLite)

Файл `companies.db` рядом с модулем. Единственная таблица `companies`:

| Колонка | Описание |
|---|---|
| `key` | **Первичный ключ**: IDNO, либо `name:<Denumire>` если IDNO пуст |
| `idno`, `denumire`, `administratori`, `inregistrare` | Базовые поля из поиска |
| `forma_juridica`, `lichidata`, `adresa` | Из детальной карточки |
| `details_text` | Полный текст фрагментов карточки |
| `founders_json`, `debts_json` | Структурированные учредители и долги |
| `source` | Источник записи: `date.gov.md` или `data2b.md` |
| `updated_at` | ISO-время последнего обновления |

### Логика upsert (`db_upsert`)

```python
key = idno or ("name:" + denumire)
data = {k: v for k, v in fields.items() if v not in (None, "")}   # только непустые
if exists(key):  UPDATE перечисленных колонок
else:            INSERT
```

Два важных следствия:

1. **Совпал IDNO → UPDATE, иначе INSERT** — требование задачи выполняется на
   уровне ключа, без дублей при повторных поисках.
2. **Обновляются только непустые поля** — повторный поиск (где нет адреса и
   учредителей) не затирает ранее загруженные детали.

Записи без IDNO не теряются: они получают ключ `name:<Название>`.

### Миграция

`db_init()` создаёт таблицу и через `PRAGMA table_info` добавляет недостающие
колонки (`founders_json`, `debts_json`, `source`) в базах, созданных ранними
версиями.

## 4. Слой получения данных (Selenium)

Страницы `open/company-search` и `open/company-details` защищены **невидимой
reCAPTCHA**: прямой `POST` на `/open/data/53d50fd1-…` возвращает `400` без
валидного токена. Поэтому данные получаются через реальное окно Chrome.

`BrowserWorker(threading.Thread)` — один поток на запрос, два режима:

| Режим | Поле формы | Ожидание результата |
|---|---|---|
| `search` | `input[name='q']` | Появление `table` с непустым `tbody` |
| `details` | `input[name='idno']` | `#fragments-accordion`, затем **исчезновение** `.fragment-loading` и появление `.output-data .simple-title, .output-data table` |

Особенности:

- Кнопка отправки — `#access-service` (форма Alpaca).
- Контент карточки **догружается AJAX-ом после капчи**, поэтому недостаточно
  дождаться самого аккордеона — ожидание построено на исчезновении спиннера.
- Перед чтением текста все секции принудительно раскрываются через
  `execute_script`, иначе `innerText` свёрнутых блоков пуст.
- Headless-режим доступен флагом, но **не рекомендуется**: Google выдаёт
  headless-браузеру ручную проверку, и запрос падает по таймауту (проверено).

### Ответ «нет данных» (`_wait_fragment`)

Портал отвечает одним из двух способов: содержательным фрагментом (таблица
результатов или поля карточки) либо коротким сообщением
«Rezultat căutare persoană juridică — **Nu sunt date.**» — так он отвечает,
например, на IDNO `1007602003320`.

Раньше второй случай не отличался от «ещё грузится», и поиск впустую ждал полный
таймаут (~120 с), завершаясь ошибкой. Теперь `_wait_fragment()` ждёт, пока
исчезнет `.fragment-loading`, и различает ответы **структурно**:

| Что найдено в `.output-data` | Вывод |
|---|---|
| `table` или `.simple-title` | Пришли данные → обычный разбор |
| Только текст | Портал сообщил, что данных нет |

Во втором случае worker сразу отправляет `("portal_no_data", текст)` и
`("search_done", [])` (для карточки — `("details_none", idno)`) и закрывает
браузер. Проверка структурная, а не по фразе, поэтому не зависит от языка
интерфейса портала.

Живой замер на IDNO `1007602003320`: **47 с** вместо ~167 с (время уходит на
старт Chrome и капчу, само определение — мгновенное).

## 4a. Второй источник: data2b.md

Портал отдаёт не все действующие компании (проверено на IDNO `1007602003320`),
поэтому параллельно опрашивается справочник **data2b.md**.

Сайт — React-SPA; его страница поиска обращается к открытому адресу
`https://data2b.md/api/companies/?q=<текст>&page=<N>`, который отвечает
**без ключа, без регистрации и без капчи**. Утилита делает ровно такой же
простой запрос обычным `urllib` (новых зависимостей не потребовалось).

| Элемент | Назначение |
|---|---|
| `data2b_fetch()` | Один HTTP-запрос, возвращает разобранный JSON |
| `data2b_parse()` | JSON → записи приложения (`idno`, `denumire`, `adresa`, `source`) |
| `data2b_total()` | Общее число совпадений для строки состояния |
| `data2b_search()` | Постраничный добор (по 10 на страницу), дедупликация |
| `Data2bWorker` | Поток; кладёт в очередь `("d2b_done", …)` / `("d2b_error", …)` |

### Параллельность и объединение

`on_search()` запускает **оба** источника сразу и выставляет счётчик
`_search_pending`; кнопки разблокируются, когда завершится последний
(`_search_task_finished()`). Второй источник необязателен: его ошибка
(`d2b_error`) лишь пишется в строку состояния и не мешает порталу.

Результаты сводятся `_merge_rows()` — дедупликация по IDNO, портал первым.
В базе действует обычный upsert, обновляющий **только непустые** поля, поэтому
короткая запись data2b.md не затирает полную карточку портала, а её адрес
дополняет уже имеющуюся запись.

`db_save_search_rows()` сохраняет, помимо колонок таблицы (`COLUMNS`), ещё
`adresa` и `source`. Колонка `source` добавляется в старые базы миграцией
в `db_init()`.

**Детальная карточка data2b.md не используется:** она запрашивается по
зашифрованному идентификатору (`/ro/api/companies/<base64>/`) и требует
браузерной сессии. Задача второго источника — только простой поиск; детали
берутся с портала кнопкой «Данные по IDNO».

## 4b. Настройки источников и самоперезапуск

### Запоминаемые источники (`settings.json`)

`settings_load()` / `settings_save()` хранят рядом с программой файл
`settings.json` с четырьмя флагами: `src_gov`, `src_d2b`, `src_db`, `headless`.
Файл не критичен: если он отсутствует или повреждён, берутся значения по
умолчанию (все источники включены, headless выключен).

В интерфейсе это группа переключателей **«Источники»**; на каждую переменную
повешен `trace_add("write", …)`, поэтому состояние сохраняется сразу при клике,
а не только при выходе. Аргумент `--no-data2b` имеет приоритет над сохранённым
значением.

`on_search()` учитывает флаги: запускает только включённые онлайн-источники, а
если выключены оба — сразу показывает выборку из локальной базы
(`status_sources_off`), не создавая потоков.

### Самоперезапуск (`_restart_app`)

Меню **«Файл → Перезапустить»**. Порядок важен: сначала сохраняются настройки,
затем **останавливается HTTP-сервер** (`shutdown()` + `server_close()`) и трей —
иначе новый процесс не сможет занять тот же порт, — и только потом
`subprocess.Popen` запускает новый экземпляр и старое окно уничтожается.

Команда собирается из `sys.executable` и `sys.argv[1:]`, с учётом сборки
PyInstaller (`sys.frozen`), поэтому аргументы (`--port`, `--lang`, …)
наследуются. Проверено вживую: старый процесс завершается, новый поднимает тот
же порт с другим PID.

## 6. HTTP-слой (`ApiHandler`)

`ThreadingHTTPServer` на `127.0.0.1:<port>`, запускается демон-потоком.
Обработчик хранит ссылку на приложение в атрибуте класса `ApiHandler.app`.

| Эндпоинт | Блокирующий | Описание |
|---|---|---|
| `/health` | нет | Статус, версия, число записей |
| `/search` | нет | Поиск **по БД** (JSON/XML) |
| `/card` | нет | Карточка из БД по IDNO (XML/JSON) |
| `/open` | нет | Показать окно и запустить поиск (`202`) |
| `/pick` | **да** | Ожидание выбора пользователя, возврат карточки |
| `/` | нет | HTML-справка |

### Механика `/pick`

```python
def submit_pick(self, q, lang, timeout):
    ev = threading.Event(); holder = {}
    self.queue.put(("pick", {...,"event": ev, "holder": holder}))
    return holder if ev.wait(timeout) else None
```

Поток HTTP-запроса **блокируется на `Event`**, а главный поток Tk тем временем
показывает окно и кнопку «Вернуть контрагента». По нажатию:

1. `on_return_pick()` → `resolve_pick(idno)`.
2. Если деталей в БД нет — запускается `BrowserWorker("details")`, и возврат
   откладывается до его завершения (`pick_after_details`).
3. `_finish_pick()` кладёт XML и запись в `holder`, вызывает `event.set()` —
   HTTP-поток просыпается и отвечает.

Отмена (выход из программы) выставляет `holder["cancelled"] = True`.

### Согласование формата ответа

| Условие | Ответ |
|---|---|
| Задан `return_to` | **302 Redirect** обратно в вызывающую систему |
| `format=html` или `Accept: text/html` | HTML-страница карточки |
| Иначе | Чистый XML (`application/xml`) |

### Возврат в вызывающую систему (`return_to`)

Если передан `return_to=<URL>`, после выбора браузер **уходит обратно** в
вызывающую систему: `_redirect()` формирует `302` и добавляет в query-строку
поля `status`, `state`, `idno`, `denumire`, `adresa`, `inregistrare`,
`forma_juridica`, `lichidata`, `administratori`, **сохраняя исходные параметры
адреса**. Параметр `state` (до 120 символов) возвращается без изменений — им
удобно передавать идентификатор документа.

Принимаются только схемы `http://` и `https://`; прочие значения игнорируются.
Статусы: `ok`, `cancelled`, `timeout`.

## 7. GUI (`App(tk.Tk)`)

- **`ttk.Panedwindow`** делит окно: сверху `ttk.Notebook` с двумя вкладками
  (онлайн-поиск / только БД), снизу — карточка `ttk.Labelframe` (master-detail).
- Обе вкладки строятся одной функцией `_build_search_tab(parent, online)`;
  таблицы — `ttk.Treeview` с `selectmode="extended"` (для массового экспорта) и
  словарём `tree._idno_map` (iid → IDNO).
- Карточка: название на всю ширину + компактная сетка **6 колонок** (три пары
  «подпись: значение» в ряд) + текстовая область деталей.
- Кнопка **«↩ Вернуть контрагента»** создаётся всегда, но пакуется в layout
  только на время внешнего запроса (`_show_return_button`).

### Локализация

Словарь `TR[lang][key]` для `en` / `ru` / `ro`; метод `App.t(key, **kw)` c
`str.format`. `retranslate()` переприсваивает тексты всем виджетам, включая
заголовки колонок `Treeview` и пункты меню (по индексам). Переключение языка
происходит без перезапуска.

### Жизненный цикл

- Закрытие окна крестиком при работающем сервере → `withdraw()` (уход в фон),
  иначе → выход.
- `do_quit()` снимает флаг `_alive` (чтобы `_poll_queue` не планировал новый
  `after` на уничтоженном окне), отменяет ожидающий `/pick`, останавливает
  HTTP-сервер и иконку трея, затем `destroy()`.

## 8. Режимы запуска

| Режим | Как | Поведение |
|---|---|---|
| Обычный | `./run.sh` | GUI + HTTP-API + трей |
| Только GUI | `--no-server --no-tray` | Без интеграции |
| Стартовый поиск | `--q "ТЕКСТ" --lang ro` | Открыть и сразу искать |
| **One-shot** | `--q "…" --pick --out card.xml` | Дождаться выбора, записать XML в файл (или stdout), выйти |

One-shot удобен, когда внешняя программа не хочет держать резидентный процесс:
она запускает утилиту на каждый вызов и читает результат из файла.

## 10. Известные ограничения

- Требуется установленный **Google Chrome**; headless заблокирован капчей.
- Для строк без IDNO детальная карточка недоступна (нет ключа запроса).
- HTTP-API без аутентификации — рассчитан **только на loopback**
  (`127.0.0.1`); не открывайте порт наружу.
- Иконка трея зависит от платформы: на части систем (например, macOS при
  запуске не из главного потока) `pystray` может быть недоступен — приложение
