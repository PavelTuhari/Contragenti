# Хаб справочника контрагентов una.md

Локальные копии **Contragenti** в фоне присылают свои базы; хаб принимает
пакет, ставит его в очередь и асинхронно вливает в справочник **una.md**,
постепенно собирая единый реестр организаций.

```
Contragenti (ПК 1) ─┐
Contragenti (ПК 2) ─┼─► POST /api/v1/batches ─► inbox ─► очередь ─► Oracle una.md
Contragenti (ПК N) ─┘        (gzip sqlite)                            TMS_UNIVERS
                                                                      TMS_ORG
                                                                      TMS_ORG26
```

Приём и импорт разделены намеренно: пакет принимается и переживает
перезапуск, даже когда Oracle недоступна. Реестр заданий хаб держит в
собственном SQLite и после старта дочитывает незавершённые пакеты.

---

## Запуск

```bash
# зависимости
.venv\Scripts\python -m pip install -r requirements.txt

# хаб (локально)
set ORA_PWD=пароль
set ORACLE_CLIENT_DIR=C:\oracle\instantclient_19_28
.venv\Scripts\python -m hub.app

# при выносе на хостинг
.venv\Scripts\python -m hub.app --host 0.0.0.0 --port 8800
```

Дашборд: `http://127.0.0.1:8800/` — пакеты, очередь, счётчики, обновление
каждые 3 секунды.

### Настройка

Файл `hub_config.json` рядом с проектом (переменные окружения имеют приоритет):

```json
{
  "host": "127.0.0.1",
  "port": 8800,
  "max_upload_mb": 64,
  "import_workers": 1,
  "clients": { "ключ-клиента-1": "Бухгалтерия", "ключ-клиента-2": "Отдел продаж" },
  "oracle": {
    "dsn": "192.168.0.24:1521/clouddev.world",
    "user": "paralax",
    "password": "",
    "client_dir": "C:/oracle/instantclient_19_28"
  }
}
```

> Пустой `clients` означает приём **без ключа** — это допустимо только на
> локальном стенде. На хостинге ключи обязательны, иначе в справочник сможет
> писать кто угодно.

## API

Базовый путь `/api/v1`. Заголовки: `X-Api-Key` — ключ клиента,
`X-Client-Id` — произвольная метка машины (по умолчанию имя хоста).

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/batches` | принять пакет: тело — **gzip(sqlite)**, без обёрток |
| `GET` | `/batches/{id}` | статус пакета и журнал событий |
| `GET` | `/batches?limit=50&status=done` | список пакетов |
| `GET` | `/stats` | сводные счётчики и клиенты |
| `GET` | `/health` | живость и глубина очереди |

Приём отвечает сразу — клиент не ждёт импорта:

```json
HTTP 202
{ "batch_id": "bf7757bd3adc4242", "status": "accepted",
  "size_bytes": 11391, "sha256": "636e27…",
  "status_url": "/api/v1/batches/bf7757bd3adc4242" }
```

Статусы пакета: `accepted` → `importing` → `done` | `error`.

### Пример

```bash
gzip -c companies.db > batch.gz
curl -X POST http://127.0.0.1:8800/api/v1/batches \
     -H "X-Api-Key: ключ" -H "X-Client-Id: buh-01" \
     --data-binary @batch.gz
```

## Клиентская сторона

Отправку выполняет `hub_client.py`. База копируется «на горячую» через
backup API SQLite — приложение при этом продолжает работать.

```bash
# разово
.venv\Scripts\python hub_client.py --once --url http://127.0.0.1:8800

# постоянно, раз в 15 минут
.venv\Scripts\python hub_client.py --url http://127.0.0.1:8800 --interval 900
```

Из самого Contragenti: **Экспорт → Отправить базу на хаб una.md**. Если в
`tms_config.json` задан `hub_url`, приложение поднимает фоновый загрузчик при
старте:

```json
{ "hub_url": "http://127.0.0.1:8800", "hub_key": "ключ", "hub_interval": 900 }
```

При недоступности хаба загрузчик не мешает работе: удваивает паузу (до двух
часов) и продолжает попытки.

## Что происходит при импорте

Каждая организация ложится тремя связанными блоками — так же, как при прямой
отправке из приложения:

| Блок | Содержимое |
|---|---|
| `TMS_UNIVERS` | `DENUMIREA` — сокращённое название, `NAMERUS` — оригинал, `CODVECHI` = IDNO, `GR1='E'` |
| `TMS_ORG` | `CODFISCAL`, юридический адрес, руководитель |
| `TMS_ORG26` | нормализованные тип предприятия и юридическая форма |

Дубли отсекаются по фискальному коду, причём на двух уровнях: проверкой перед
вставкой и штатным триггером `TRIG_UNIVERS_UNQ_CODVECHI` — при `GR1='E'`
база сама не даст завести вторую организацию с тем же кодом.

Записи без IDNO пропускаются: сравнивать их не по чему, и при каждом новом
пакете они бы задваивались.

## Дальнейший шаг: Oracle APEX

Сейчас хаб пишет напрямую в таблицы `PARALAX`. Переход на APEX не потребует
переделки клиентов — меняется только приёмник внутри `hub/importer.py`:
контракт API, формат пакета и логика дедупликации остаются прежними.
