# AGENTS.md — правила для любого ИИ-агента и разработчика этого репозитория

Прочитай перед любой доработкой. Правила обязательны для всех частей проекта:
Contragenti (`company_search.py`), Demo CRM (`crm_delphi/`), хаб (`hub/`),
интеграции una.md (`tms_*.py`, `goods_*.py`), SDK (`sdk/`).

## 1. Тестовые данные — всегда и в полном объёме

При **любом** развитии проекта (новая сущность, поле, режим, миграция схемы,
рефакторинг слоя данных) обязательно:

1. **Обновить генератор тестовых данных** так, чтобы он покрывал новую
   сущность/поле полным набором реалистичных записей (не 1–2 строки, а
   рабочий объём небольшой фирмы: десятки клиентов, контактов, лидов, сделок,
   позиций номенклатуры, заказов со строками, задач; все статусы/виды/этапы
   должны встречаться).
2. **Запустить генерацию** и убедиться, что она проходит без ошибок:

   ```bat
   crm_delphi\ContragentiCRM.exe --seed-demo [путь_к_базе]
   ```

   Без аргумента заполняется `clients.db` рядом с exe (существующие записи
   не трогаются, добавляются недостающие). Для чистого набора укажи новый
   файл. Python-часть: `company_search.py --selftest` (разбор XML, SQLite).
3. **Протестировать все режимы на DML-операции** — для каждой сущности
   INSERT → SELECT → UPDATE → SELECT → DELETE → COUNT, плюс специфика:
   строки заказа (добавить/пересчитать/убрать), проводка остатков
   (продажа списывает, производство приходует, услуга не меняет), конвертация
   лида, дедупликация клиента по IDNO, фильтры и пресеты:

   ```bat
   crm_delphi\ContragentiCRM.exe --dml-test
   ```

   Работает во временной базе, код возврата 0 = всё прошло, 1 = есть FAIL
   (подробности в stdout). Затем GUI-самотест, он тоже обязателен:

   ```bat
   crm_delphi\ContragentiCRM.exe --gui-test shots_gui
   ```

4. Если добавлена сущность — добавить шаги в `uGuiSelfTest.pas` (создание,
   изменение, удаление через интерфейс) и записи в `uTestData.pas`
   (генератор + DML-проверки). Коммит без этого не считается завершённым.
5. Если затронуты этапы процесса, отчёты или выгрузка — проверить, что
   плитки рабочего стола заполнены по всем этапам (в генераторе должны
   быть заказы и на просрочке, и в срок), а каждый отчёт выгружается в
   оба формата: xlsx должен начинаться с `PK`, pdf — с `%PDF`
   (`uTestData.pas` проверяет это по сигнатуре файла, а не по расширению).

Итог каждой доработки: генератор прошёл, DML-тест 0 FAIL, GUI-самотест
N/N, акт `crm_delphi/act_testirovaniya.html` пересобран.

## 2. Интерфейс

- **Никаких модальных окон.** Сообщения — в цветную строку внизу
  (`Say(mkInfo/mkOk/mkWarn/mkErr, …)`), редакторы — панели внутри страниц,
  подтверждение удаления — повторным нажатием, необработанные исключения —
  через `Application.OnException` в строку сообщений. Модальные диалоги
  ломают самотест и headless-режимы.
- Стиль — EspoCRM (тема «Espo»), палитра и фабрики в `uEspoTheme.pas`.
- Новый раздел CRM = запись `TEntityDef` в `uCrmData.pas` + страница
  `TEntityPage`, а не новая форма.
- **Все видимые тексты — только из `crm_delphi/lang.json`** через `T.S` /
  `T.F` / `T.EnumAt`. Новый текст сразу добавляй во все три языка
  (ro/en/ru). Значения перечислений в базе остаются каноническими
  (`ENUM_*` в `uCrmData.pas`), переводится только показ, соответствие —
  по позиции: порядок в JSON менять нельзя.
- Язык хранится в реестре `HKCU\Software\DemoCRM\Language`, не в `crm.ini`.
- Мышиные действия (перетаскивание карточек канбана, полос Ганта,
  задач календаря) должны
  проходить через те же методы, что и кнопки: у канбана это
  `MoveCardTo`, у Ганта — `CommitDrag`. Для самотеста у каждой страницы
  есть хук, повторяющий последовательность мыши (`DragCardById`,
  `DragBar`), — новые мышиные жесты покрывай так же.
- Канбан и схема бизнес-процесса показывают **одни и те же карточки** из
  `uBoardCards.pas` (`LoadBoardCards`) и меняют этап **только** через
  `MoveBoardCard`. Новое поле на карточке — в `TBoardCard` и `MakeBoardCard`,
  а не в двух местах. Анимация переноса считает кадры (`AnimFrames`) —
  самотест проверяет, что она отработала, но она не должна быть обязательной
  для логики (`AnimEnabled := False` даёт тот же результат).
- Описание бизнес-процессов — внешний `crm_delphi/processes.json` (узлы с
  `board`/`col` привязаны к колонкам канбана; тексты по языкам ro/en/ru).
  Новая колонка канбана = новый узел в JSON; самотест работает с **копией**
  файла (`LoadFrom`), файл проекта не трогает.
- Мышиные хуки самотеста передают координаты **относительно контрола**
  (как их даёт VCL реальной мыши), а не двигают физический курсор:
  `SetCursorPos` не работает в заблокированном/удалённом сеансе, и тест
  падал именно там, где его гоняют без присмотра.
- Даты по умолчанию задаются сентинелом `today` / `today+N` в `TFieldDef`
  и раскрываются через `ResolveDefault`. Не подставляй сегодняшнюю дату
  всем полям типа даты подряд: так новый заказ получал дату отгрузки и
  сразу считался отгруженным.

## 3. Тесты — только реальные сценарии

- Самотест должен проходить настоящий путь: кнопка → SDK → процесс
  Contragenti → XML → база. Снимки чужих окон делает сам Contragenti
  (`--shots-dir`), потому что межпроцессный PrintWindow/BitBlt в этой среде
  возвращает пустой кадр.
- Портал date.gov.md после нескольких поисков подряд показывает reCAPTCHA.
  Капчу **не обходить**; `--auto-pick` сначала берёт компанию из локального
  кэша и идёт на портал только если её там нет.
- Отчёт — один самодостаточный HTML с встроенными снимками
  (`act_testirovaniya.html`).

## 3.1. Данные и SQL

- Пустое число сохраняется как **NULL**, а не пустая строка: SQLite
  типизирует значения по факту, и текст `''` ломает сравнения
  `COALESCE(x,0) > 0` (в SQLite текст больше любого числа).
- Условия этапов и пресетов пишутся через префикс `t.`, поэтому любой
  запрос, куда они подставляются, обязан объявлять псевдоним `t`
  (см. `TCrmData.Count`).
- Деньги и количества — всегда с точкой в SQL независимо от локали
  Windows (в коде для этого отдельный `TFormatSettings`).

## 4. Сборка и кодировки

- Delphi 10.2 Tokyo, консольный `dcc32` (`crm_delphi/build.bat`), без
  inline-`var`. Все `.pas/.dpr` — UTF-8 **с BOM** (иначе кириллица в
  интерфейсе превращается в мусор); после правки инструментом, который BOM
  снимает, вернуть его перед сборкой.
- `build.bat` только ASCII в `rem` (cmd читает OEM-кодировку).
- GUI-exe не пишет в pipe — при headless-запусках перенаправлять вывод в
  файл, не в `subprocess.PIPE`.
- Собранный `crm_delphi/ContragentiCRM.exe` коммитится намеренно: он
  попадает в MSI (`setup.py`, `DemoCRM/`) без RAD Studio на машине сборки.

## 4.1. Установка (MSI) и мастер настройки

- `setup.py` собирает MSI; первым `Executable` идёт `setup_wizard.py`
  («Contragenti Setup.exe») — его cx_Freeze запускает по «Launch on finish».
  Не менять порядок.
- Мастер после MSI проверяет команду `python` (как в PowerShell). Если она
  не работает — запускает `python` без аргументов: на свежих Windows
  интерпретатор ставится сам (App Installer / Store), версия не фиксируется.
  `--offline` и `--no-python` этот шаг пропускают. Описание — `INSTALL_MSI_ru.md`.
- Мастер докачивает компоненты по `release.json` из ветки `main`
  (`raw.githubusercontent.com`). При любом изменении файлов, которые попадают
  в установку без переустановки (`ContragentiCRM.exe`, `lang.json`,
  `processes.json`, инструкции, SDK), проверь список `components`; при выпуске
  новой версии подними `version` в `release.json`, `VERSION`, `APP_VERSION`
  в `setup.py` и `company_search.py` (все четыре — одно значение).
- Стартовая база компаний — `data/companies_seed.zip`
  (`python tools/make_seed.py`); в `.gitignore` для неё исключение из `*.zip`.
- Готовые сборки лежат в репозитории, в `release/`: MSI и zip-пакет
  обновления. Zip пересобирает `tools/make_release.py --zip-only` — он
  вызывается из `crm_delphi\build.bat` после компиляции и из pre-commit
  хука (`.githooks/pre-commit`; включить один раз:
  `git config core.hooksPath .githooks`). Zip детерминированный, без
  изменений содержимого не меняется. Список файлов пакета — `FILES` в
  `make_release.py`: новый файл, который должен обновляться поверх
  установки, добавляй туда (и в `components` release.json как запасной
  путь). После `python setup.py bdist_msi` выполни
  `python tools/make_release.py` — MSI попадёт в `release/`, а в
  `release.json` обновятся `msi_url`, размер и sha256.
- Перед коммитом: `python setup_wizard.py --check --offline --no-seed`
  должен закончиться с кодом 0 (паспорт, настройка, самопроверка Demo CRM).
  После пуша — `--check` без `--offline` (проверяет `release.json` и
  загрузку с GitHub).
- Отчёт мастера при ошибке (паспорт + лог + события MsiInstaller) только
  предлагается к отправке (issue / mailto) — ничего не уходит автоматически,
  и в отчёт не должны попадать пароли/ключи (`crm.ini` с ключом ERP не
  включать целиком).

## 5. Секреты и Git

- Пароли только из переменных окружения или gitignored-конфигов
  (`tms_config.json`, `hub_config.json`, `goods_config.json`,
  `deploy/.env`). В коде и в тестовых утилитах — никаких значений по
  умолчанию с паролями.
- Коммиты и пуш — как **Pavel Tuhari `<ptuhari@gmail.com>`** (локальный
  `git config` репозитория), не глобальной учёткой этой машины. Подробности
  подключения — `F:\grok\CLAUDE_GIT_CONNECT.md` (локальный runbook).
- `build/`, `dist/`, `*.db`, логи — не коммитить.
