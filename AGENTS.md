# AGENTS.md — правила для любого ИИ-агента и разработчика этого репозитория

Прочитай перед любой доработкой. Правила обязательны для всех частей проекта:
Contragenti (`company_search.py`), Demo CRM (`crm_delphi/`), хаб (`hub/`),
интеграции una.md (`tms_*.py`, `goods_*.py`), SDK (`sdk/`).

## 1. Тестовые данные — всегда и в полном объёме

При **любом** развитии проекта (новая сущность, поле, режим, миграция схемы,
рефакторинг слоя данных) обязательно:

1. **Обновить генератор тестовых данных** так, чтобы он покрывал новую
   сущность/поле полным набором реалистичных записей (не 1–2 строки, а
   рабочий объём небольшой фирмы: десятки клиентов, контактов, лидов, сделок,
   позиций номенклатуры, заказов со строками, задач; все статусы/виды/этапы
   должны встречаться).
2. **Запустить генерацию** и убедиться, что она проходит без ошибок:

   ```bat
   crm_delphi\ContragentiCRM.exe --seed-demo [путь_к_базе]
   ```

   Без аргумента заполняется `clients.db` рядом с exe (существующие записи
   не трогаются, добавляются недостающие). Для чистого набора укажи новый
   файл. Python-часть: `company_search.py --selftest` (разбор XML, SQLite).
3. **Протестировать все режимы на DML-операции** — для каждой сущности
   INSERT → SELECT → UPDATE → SELECT → DELETE → COUNT, плюс специфика:
   строки заказа (добавить/пересчитать/убрать), проводка остатков
   (продажа списывает, производство приходует, услуга не меняет), конвертация
   лида, дедупликация клиента по IDNO, фильтры и пресеты:

   ```bat
   crm_delphi\ContragentiCRM.exe --dml-test
   ```

   Работает во временной базе, код возврата 0 = всё прошло, 1 = есть FAIL
   (подробности в stdout). Затем GUI-самотест, он тоже обязателен:

   ```bat
   crm_delphi\ContragentiCRM.exe --gui-test shots_gui
   ```

4. Если добавлена сущность — добавить шаги в `uGuiSelfTest.pas` (создание,
   изменение, удаление через интерфейс) и записи в `uTestData.pas`
   (генератор + DML-проверки). Коммит без этого не считается завершённым.

Итог каждой доработки: генератор прошёл, DML-тест 0 FAIL, GUI-самотест
N/N, акт `crm_delphi/act_testirovaniya.html` пересобран.

## 2. Интерфейс

- **Никаких модальных окон.** Сообщения — в цветную строку внизу
  (`Say(mkInfo/mkOk/mkWarn/mkErr, …)`), редакторы — панели внутри страниц,
  подтверждение удаления — повторным нажатием, необработанные исключения —
  через `Application.OnException` в строку сообщений. Модальные диалоги
  ломают самотест и headless-режимы.
- Стиль — EspoCRM (тема «Espo»), палитра и фабрики в `uEspoTheme.pas`.
- Новый раздел CRM = запись `TEntityDef` в `uCrmData.pas` + страница
  `TEntityPage`, а не новая форма.

## 3. Тесты — только реальные сценарии

- Самотест должен проходить настоящий путь: кнопка → SDK → процесс
  Contragenti → XML → база. Снимки чужих окон делает сам Contragenti
  (`--shots-dir`), потому что межпроцессный PrintWindow/BitBlt в этой среде
  возвращает пустой кадр.
- Портал date.gov.md после нескольких поисков подряд показывает reCAPTCHA.
  Капчу **не обходить**; `--auto-pick` сначала берёт компанию из локального
  кэша и идёт на портал только если её там нет.
- Отчёт — один самодостаточный HTML с встроенными снимками
  (`act_testirovaniya.html`).

## 4. Сборка и кодировки

- Delphi 10.2 Tokyo, консольный `dcc32` (`crm_delphi/build.bat`), без
  inline-`var`. Все `.pas/.dpr` — UTF-8 **с BOM** (иначе кириллица в
  интерфейсе превращается в мусор); после правки инструментом, который BOM
  снимает, вернуть его перед сборкой.
- `build.bat` только ASCII в `rem` (cmd читает OEM-кодировку).
- GUI-exe не пишет в pipe — при headless-запусках перенаправлять вывод в
  файл, не в `subprocess.PIPE`.
- Собранный `crm_delphi/ContragentiCRM.exe` коммитится намеренно: он
  попадает в MSI (`setup.py`, `DemoCRM/`) без RAD Studio на машине сборки.

## 5. Секреты и Git

- Пароли только из переменных окружения или gitignored-конфигов
  (`tms_config.json`, `hub_config.json`, `goods_config.json`,
  `deploy/.env`). В коде и в тестовых утилитах — никаких значений по
  умолчанию с паролями.
- Коммиты и пуш — как **Pavel Tuhari `<ptuhari@gmail.com>`** (локальный
  `git config` репозитория), не глобальной учёткой этой машины. Подробности
  подключения — `F:\grok\CLAUDE_GIT_CONNECT.md` (локальный runbook).
- `build/`, `dist/`, `*.db`, логи — не коммитить.
