# Contragenti — интеграция через локальный API

Утилита поднимает локальный HTTP-сервер (по умолчанию `http://127.0.0.1:9393`),
через который внешние программы (1С, браузер, нативные приложения) могут
запускать поиск и получать карточку контрагента в формате **XML** или **JSON**.

- Базовый адрес: `http://127.0.0.1:<port>` (порт задаётся `--port`, по умолчанию `9393`).
- Только локальные вызовы (`127.0.0.1`). Аутентификация не предусмотрена — сервис
  рассчитан на локальную машину пользователя.
- CORS разрешён (`Access-Control-Allow-Origin: *`) — можно вызывать из браузера
  через `fetch`.
- Метод — `GET`, параметры передаются в query-строке.

---

## 1. Эндпоинты

### `GET /health`
Проверка доступности. Ответ JSON:

```json
{ "status": "ok", "version": "1.0", "db_count": 20 }
```

### `GET /search?q=ТЕКСТ&format=json|xml`
Поиск **по локальной базе** (без обращения к сайту). `q` пустой — вернуть всё.

- `format=json` — массив записей.
- `format=xml` (по умолчанию) — список `<item idno="…">Название</item>`.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<results><item idno="1003600116460">CENTRUL … UNISIM-SOFT S.R.L.</item></results>
```

### `GET /card?idno=IDNO&format=xml|json`
Карточка компании **из базы** по IDNO.
- `200` — карточка (XML по умолчанию, либо JSON).
- `404` — если IDNO нет в базе.

### `GET /open?q=ТЕКСТ&lang=ru|ro|en`
Показать окно утилиты, переключить язык и запустить онлайн-поиск по `q`.
Возвращает сразу `202` (не ждёт действий пользователя).

### `GET /pick?q=ТЕКСТ&lang=ru|ro|en&timeout=СЕК&format=`
**Основной сценарий интеграции.** Открывает окно с готовым поиском на нужном
языке; на форме появляется заметная кнопка **«Вернуть контрагента»**. Утилита
**ждёт**, пока пользователь выберет компанию и нажмёт эту кнопку.

- `200` — пользователь выбрал контрагента. Если детали ещё не были загружены,
  утилита дозагрузит их с сайта перед возвратом.
- `204` — пользователь отменил (закрыл утилиту).
- `504` — истёк `timeout` (по умолчанию `300` секунд).

**Формат ответа `200` (согласование):**
- Программный клиент (1С, `curl`, `fetch` с `Accept: */*` или `application/xml`)
  получает **чистый XML** карточки (`application/xml`).
- Браузер (переход по ссылке, `Accept: text/html`) получает **HTML-страницу** с
  основными полями, таблицами учредителей/долгов и полным XML в блоке `<pre>`.
- Можно принудительно задать: `format=xml` или `format=html`.

### Возврат в вызывающую систему: `return_to` и `state`

Если вызывающая система — веб-приложение (портал, 1С в браузере, CRM), удобнее
не разбирать ответ, а **вернуть пользователя обратно** к себе вместе с данными.
Для этого передайте адрес возврата:

```
GET /pick?q=UNISIM&lang=ru&return_to=<URL-encoded адрес>&state=<ваш идентификатор>
```

После выбора утилита отвечает **`302 Redirect`** на ваш `return_to`, добавляя в
query-строку поля (исходные параметры адреса сохраняются):

| Параметр | Значение |
|---|---|
| `status` | `ok` \| `cancelled` \| `timeout` |
| `state` | Ваш идентификатор, возвращается без изменений (до 120 символов) |
| `idno`, `denumire`, `adresa`, `inregistrare`, `forma_juridica`, `lichidata`, `administratori` | Поля выбранной компании |

Пример. Запрос:

```
/pick?q=UNISIM&lang=ru&return_to=http%3A%2F%2Flocalhost%3A8080%2F1c%2Fcallback%3Fdoc%3D77&state=ABC123
```

Ответ — `302 Location:`

```
http://localhost:8080/1c/callback?doc=77&status=ok&state=ABC123
    &idno=1003600116460&denumire=CENTRUL+…+UNISIM-SOFT+S.R.L.
    &adresa=mun.+Chi%C5%9Fin%C4%83u%2C+…&inregistrare=30.03.2001
    &forma_juridica=Societate+cu+r%C4%83spundere+limitat%C4%83&lichidata=Nu
```

Полный XML при этом всегда можно дочитать отдельным вызовом
`GET /card?idno=<полученный IDNO>&format=xml`.

> Допускаются только адреса со схемой `http://` или `https://`; иные значения
> `return_to` игнорируются. При заданном `return_to` HTML-карточка не
> показывается (браузер уходит в вашу систему), если явно не указан `format=html`.

### `GET /`
HTML-страница со справкой по эндпоинтам (удобно открыть в браузере).

## 2. Формат XML карточки

```xml
<?xml version="1.0" encoding="UTF-8"?>
<counterparty source="date.gov.md" idno="1003600116460" updated="2026-08-11T00:58:37">
  <idno>1003600116460</idno>
  <denumire>CENTRUL … UNISIM-SOFT S.R.L.</denumire>
  <inregistrare>30.03.2001</inregistrare>
  <forma_juridica>Societate cu răspundere limitată</forma_juridica>
  <lichidata>Nu</lichidata>
  <adresa>mun. Chişinău, sec. Buiucani, str. Alba-Iulia, 75/B</adresa>
  <administratori>TUHARI PAVEL [Administrator]</administratori>
  <source>date.gov.md</source>
  <founders>
    <founder name="TUHARI PAVEL" share="100,00"/>
  </founders>
  <debts currency="MDL">
    <debt nr="1" type="Bugetul de stat și local" sum="0,00"/>
    <debt nr="2" type="Bugetul de stat" sum="180,78"/>
  </debts>
  <details_text>…полный текст карточки…</details_text>
</counterparty>
```

Элементы `founders`/`debts` могут быть пустыми, если данных нет.

Атрибут и элемент `source` показывают, откуда получена запись:
`date.gov.md` (полная карточка) или `data2b.md` — второй источник, который
используется для компаний, отсутствующих на портале. У записей из data2b.md
заполнены только `idno`, `denumire` и `adresa`; остальные поля появятся после
запроса деталей на портале.

## 3. Примеры вызова

### curl

```bash
curl "http://127.0.0.1:9393/health"
curl "http://127.0.0.1:9393/card?idno=1003600116460&format=xml"
# Открыть окно с выбором и получить XML выбранного контрагента:
curl "http://127.0.0.1:9393/pick?q=UNISIM&lang=ru&timeout=300"
```

### Браузер / JavaScript (fetch)

```js
const r = await fetch("http://127.0.0.1:9393/pick?q=UNISIM&lang=ru");
if (r.status === 200) {
  const xml = await r.text();   // XML карточки выбранного контрагента
}
```

Также можно просто открыть в браузере ссылку
`http://127.0.0.1:9393/pick?q=UNISIM&lang=ru` — откроется окно утилиты, а после
выбора браузер получит XML.

### 1С:Предприятие (сценарий «не нашли контрагента»)

Когда в 1С не найден контрагент по введённому фильтру, вызвать утилиту и получить
XML выбранной пользователем компании:

```bsl
Соединение = Новый HTTPСоединение("127.0.0.1", 9393);
Фильтр = КодироватьСтроку("UNISIM", СпособКодированияСтроки.КодировкаURL);
Запрос = Новый HTTPЗапрос("/pick?q=" + Фильтр + "&lang=ru&timeout=300");
Ответ = Соединение.Получить(Запрос);

Если Ответ.КодСостояния = 200 Тогда
    ТекстXML = Ответ.ПолучитьТелоКакСтроку("UTF-8");
    // Разобрать ТекстXML: idno, denumire, adresa, founders, debts …
ИначеЕсли Ответ.КодСостояния = 204 Тогда
    Сообщить("Выбор отменён пользователем.");
Иначе
    Сообщить("Истёк таймаут выбора.");
КонецЕсли;
```

> Совет: увеличьте таймаут HTTP-соединения в 1С, т.к. `/pick` ждёт действий
> пользователя (до `timeout` секунд).

### Веб-система с возвратом пользователя (`return_to`)

Если контрагента выбирают из веб-интерфейса, проще отправить пользователя в
утилиту ссылкой и получить его обратно вместе с данными — тело ответа разбирать
не нужно:

```html
<!-- пользователь уходит в утилиту, а затем возвращается на /1c/callback -->
<a href="http://127.0.0.1:9393/pick?q=UNISIM&lang=ru
        &return_to=http%3A%2F%2Flocalhost%3A8080%2F1c%2Fcallback%3Fdoc%3D77
        &state=ABC123">Выбрать контрагента</a>
```

На стороне вашей системы (`/1c/callback`) читаются обычные GET-параметры:

```
status=ok&state=ABC123&idno=1003600116460&denumire=…&adresa=…
```

Проверьте `status` (`ok` / `cancelled` / `timeout`), сверьте `state` со своим
документом и при необходимости запросите полный XML:
`GET /card?idno=<idno>&format=xml`.

### Запуск без постоянного сервера (одноразовый режим)

Если держать сервис в фоне нежелательно, внешняя программа может запускать
процесс на каждый вызов и читать XML из файла:

```bash
python company_search.py --q "UNISIM" --lang ru --pick --out card.xml --no-server --no-tray
# после выбора пользователем: card.xml содержит XML карточки, процесс завершается
```

## 4. Коды ответов

| Код | Значение |
|---|---|
| `200` | Успех; тело — XML / JSON / HTML |
| `202` | `/open` принят (окно показано) |
| `204` | `/pick`: пользователь отменил выбор |
| `302` | `/pick` с `return_to`: возврат в вызывающую систему (в т.ч. при отмене и таймауте — см. `status`) |
| `404` | `/card`: IDNO не найден в базе; либо неизвестный эндпоинт |
| `504` | `/pick`: истёк таймаут ожидания выбора |

---

## 5. Замечания по интеграции

- `/search` и `/card` работают **только по локальной базе** и отвечают мгновенно.
  Чтобы данные там появились, компания должна быть предварительно найдена онлайн
  (вручную или через `/pick`).
- `/pick` — интерактивный: требует участия пользователя (выбор + подтверждение),
  но гарантирует возврат актуальной карточки, дозагружая детали при необходимости.
- Онлайн-получение данных зависит от reCAPTCHA портала, поэтому выполняется в
  видимом окне Chrome. Держите утилиту запущенной в трее для быстрого отклика.
